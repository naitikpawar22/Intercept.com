# Project: NetScope – Selenium Chrome Security Testing Tool

Act as a senior software architect and developer. Build a professional Windows desktop application that combines Selenium-controlled Google Chrome, Chrome DevTools-style inspection, and Burp Suite-style HTTP/HTTPS interception.

I want a REAL WORKING APPLICATION, not just a UI prototype.

## 1. Main Requirement

Create a desktop application where I can click a button named "Launch Chrome".

When I click this button:

1. Launch a real Google Chrome browser using Selenium WebDriver.
2. Open Chrome in a separate browser window controlled by my software.
3. Allow me to browse normally inside Chrome.
4. Allow me to open any website using the Chrome address bar.
5. Capture the website's HTTP and HTTPS requests and responses.
6. Display all captured traffic inside my desktop application.
7. Allow me to inspect, edit, and forward requests and responses.

The application must work with real Chrome traffic, not sample or dummy data.

* Start the local interception proxy.
* Launch a new Chrome browser session through Selenium.
* Configure Chrome to use the local proxy.
* Open the browser window.
* Display the Chrome session status in the application.
* Allow normal website navigation.
* Allow opening multiple tabs.

## 5. Intercept ON/OFF

Create an Intercept toggle button.

When Intercept is OFF:

* Chrome should browse normally.
* Requests should pass through automatically.
* Request and response history should continue recording.

When Intercept is ON:

* Pause matching HTTP requests before they reach the server.
* Display the request immediately in my software.
* Allow me to inspect the complete request.
* Allow me to edit the request.
* Allow me to forward the modified request.
* Allow me to drop the request.
* Allow me to forward the original request.

Provide buttons:

* Forward
* Drop
* Forward Original
* Send to Repeater
* Intercept ON/OFF

Display the number of requests waiting for forwarding.

5. Allow me to inspect the response.
6. Allow me to edit the response.
7. Allow me to forward the modified response to Chrome.
8. Allow me to drop the response.

* Response headers
* JSON response body

* Plain text response body

Display both original and modified responses.

Ensure that the browser receives the modified response.

Handle Content-Length, Content-Encoding, and binary responses correctly.

## 14. Important Architecture Requirement

Selenium must launch and control a real Chrome browser.

The browser's network traffic must pass through the configured mitmproxy instance.

Use mitmproxy to capture and pause requests and responses.

Use a secure local communication channel between the desktop application and the proxy.

Use Chrome DevTools Protocol for browser debugging and inspection.

Do not rely only on Selenium performance logs for HTTPS request modification.

Do not claim that Selenium alone can intercept and modify all browser traffic.

If embedding the Chrome window inside Electron is technically unreliable, open a separate Chrome window and provide synchronized browser controls and inspection panels inside the desktop application.

Do not fake browser embedding.

## 15. Security and Testing

Do not include automatic exploitation or destructive testing.

Use a local test server to verify:

* Request capture
* Request modification
* Request forwarding
* Response capture
* Response modification
* Response forwarding
* HTTPS interception
* Normal browsing when interception is OFF
